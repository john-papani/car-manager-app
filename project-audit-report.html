Car Manager — Code Audit Report

Repository audit · Next.js 16 · TypeScript · Google Sheets backend · Generated June 29, 2026

62
Overall project health: 62 / 100

The codebase is a coherent, mobile-first MVP with clear separation between pages, API routes, sheet helpers, and entry mappers. Demo mode, caching, and form UX are thoughtfully implemented. However, API authentication gaps, single-tenant shared-sheet architecture, calendar/receipt lifecycle bugs, and missing production hardening block a higher score. The app is suitable for personal/local use today; it is not production-ready without critical security fixes.

Scope & methodology

This audit reviewed all application source under the repository root: App Router pages (app/), API route handlers (app/api/), shared libraries (lib/), client services (services/), React components (components/), Auth.js configuration (auth.ts, proxy.ts), and types (types/). No application code was modified. Findings are evidence-based from static analysis; runtime deployment behavior is marked “Needs verification” where not observable from the repo alone.

1. Architecture and code organization

The project follows a sensible Next.js App Router layout: server-rendered pages fetch data through lib/current-user-data.ts, mutations go through app/api/*, and client forms call thin fetch wrappers in services/. Entry mapping and validation live in dedicated lib/*-entry.ts modules. This is maintainable for an MVP.

2. Security and authentication

Critical

API GET endpoints expose sheet data without authentication

Files
app/api/fuel/route.ts (GET), app/api/service/route.ts (GET), app/api/expenses/route.ts (GET), app/api/vehicle/route.ts (GET)
Explanation
GET handlers call getCurrentFuelEntries() etc. without calling auth(). Because proxy.ts excludes /api/*, unauthenticated HTTP clients can fetch all entries as JSON.
// app/api/fuel/route.ts — GET has no auth() call
export async function GET() {
  const entries = (await getCurrentFuelEntries()).sort(...);
  return NextResponse.json({ entries });
}
Impact
Full vehicle cost history, odometer readings, receipt URLs, and profile data leak to anyone who can reach the deployment URL.
Fix
const session = await auth();
if (!session?.user) {
  return NextResponse.json({ message: "Unauthorized" }, { status: 401 });
}
Effort
Small
Critical

POST/PUT/PATCH/DELETE only block demo users — not unauthenticated callers

Files
All mutating API handlers except auth routes
Explanation
Handlers check isDemoSession(session) but never verify session?.user. When session is null, isDemoSession returns false and the write proceeds using the service account in lib/google.ts.
// lib/demo-mode.ts
export function isDemoSession(session) {
  return session?.user?.id === "demo-user" || session?.user?.email === "user@local.demo";
}
// null session → false → write allowed
Impact
Unauthenticated clients can create, update, and delete rows in the production spreadsheet.
Fix
Add requireAuthenticatedSession() returning 401 before any mutation; keep demo 403 separate.
Effort
Small
Critical

Hardcoded demo credentials (user / user)

Files
auth.ts lines 12–13, 77–85; app/login/page.tsx
Explanation
Credentials provider accepts fixed username/password with no environment guard. README documents this for local testing.
Impact
If deployed with Credentials provider enabled, anyone can sign in as demo user (read-only for writes, but still accesses mock flow — and combined with API gaps, behavior is unpredictable).
Fix
Gate provider on process.env.ENABLE_DEMO_LOGIN === "true"; disable in production.
Effort
Small
High

Google OAuth access token stored on client-visible session

Files
auth.ts (session callback), types/next-auth.d.ts
Explanation
session.accessToken = token.accessToken exposes the Google access token through Auth.js session endpoints. Refresh token stays in JWT only (good), but access token in session is still sensitive.
Impact
XSS or malicious browser extension could exfiltrate Drive-scoped access token while session is active.
Fix
Remove accessToken from session callback; read token from JWT inside server routes only via auth() internals or custom server-only helper.
Effort
Medium

3. Google integrations and data integrity

Critical

Single shared spreadsheet — no per-user data separation

Files
lib/sheets.ts (GOOGLE_SHEET_ID), lib/current-user-data.ts
Explanation
All non-demo users read/write the same tabs (fuel_entries, etc.). README acknowledges “Multi-user data separation is still limited.”
Impact
Not suitable for shared hosting; one user’s deletes affect everyone.
Fix
Map session.user.id → sheet ID or add owner_id column with query filters.
Effort
Large
High

Calendar events created but event ID never persisted

Files
lib/calendar.ts, lib/sheets.ts (schema), app/api/fuel/route.ts
Explanation
createFuelCalendarEvent calls calendar.events.insert but discards the returned event ID. Schema lacks calendar_event_id. DELETE handler reads entry.calendar_event_id which is never populated.
// app/api/fuel/route.ts DELETE
const calendarEventId = entry.calendar_event_id; // always undefined in practice
Impact
Calendar fills with orphan events; deletes leave stale events; repeated entries create duplicates.
Fix
Add column to schema; after insert, PATCH row with returned event.id; use on delete.
Effort
Medium
High

Non-atomic read-modify-write on Sheets

Files
lib/sheets.ts — upsertRowById, deleteRowById
Explanation
Both functions GET all rows, find index by ID, then UPDATE or DELETE by row index. Concurrent requests can race: two appends OK, but simultaneous delete+upsert can target wrong row after index shift.
Impact
Wrong row deleted or duplicate rows under concurrent use (e.g., two devices).
Fix
Retry with re-fetch; use batchUpdate with filters; long-term migrate to DB with transactions.
Effort
Medium–Large
Medium

Files
lib/sheets.ts — ensureSheetHeaders
Explanation
If first row doesn’t exactly match expected headers, code overwrites A1:N1 with schema headers. Manual edits to headers trigger rewrite (data rows safe, but header customization lost).
Impact
Unexpected header reset; confusing for manual sheet editors.
Effort
Small
Medium

4. API routes and validation

Medium

Truthy checks allow invalid numeric payloads

Files
app/api/fuel/route.ts POST, app/api/service/route.ts, app/api/expenses/route.ts
Explanation
Fuel POST: if (!body.odometer || !body.liters || !body.total_cost) rejects zero but accepts negative numbers and NaN (Number(undefined) → NaN stored). Service allows total_cost: 0 by default. Expense checks total_cost === undefined but not NaN.
// Weak validation pattern
if (!body.date || !body.odometer || !body.liters || !body.total_cost) { ... }
const entry = { odometer: Number(body.odometer), ... };
Fix
Use Zod: positive numbers, ISO date strings, max string lengths, enum categories.
Effort
Medium
High

Receipt upload: client-controlled MIME, no size cap

Files
app/api/receipts/route.ts, lib/compress-image.ts
Explanation
Server checks file.type.startsWith("image/") only. No file.size limit before buffering entire file into memory (arrayBuffer()).
Impact
Large upload memory exhaustion; MIME spoofing if downstream trusts type.
Fix
Reject > 5–8 MB; validate magic bytes; sanitize filename (already timestamps).
Effort
Small
Medium

Demo mode write protection is correctly implemented on mutating routes

Files
lib/demo-mode.ts, all POST/PUT/PATCH/DELETE handlers
Explanation
Demo session returns 403 with Greek/English message. getCurrent*Entries serves mock data. Positive finding — demo cannot write to Sheets when session check is also added.
Low

Background receipt attach can fail silently

Files
components/FuelEntryForm.tsx, components/FuelPageFeedback.tsx
Explanation
Upload runs after navigation; errors only console.error. User sees “uploading in background” toast but no failure toast.
Fix
Dispatch error event to show error toast on failure.
Effort
Small

10 most valuable next improvements

  1. Require authentication on every API route — closes the largest security hole.
  2. Disable demo login in production — prevents trivial account access.
  3. Add Zod validation to write endpoints — stops garbage/NaN data in Sheets.
  4. Implement edit flows for all entry types — highest user-value feature per README and next_steps.md.
  5. Fix calendar event ID persistence and deletion — stops orphan Google Calendar events.
  6. Keep OAuth tokens server-side only — reduces XSS blast radius.
  7. Add unit tests for fuel-calculations.ts — protects core product metrics.
  8. Surface sheet load errors in the UI — avoids misleading empty states.
  9. Receipt upload hardening (size, magic bytes, failure toasts).
  10. Plan multi-user data isolation — required before sharing the app beyond a single driver.
